# Деплой на Vercel

Застосунок розрахований на serverless: жодна частина не покладається на те, що
процес живе між запитами. Черга альбомів у базі, лічильник квоти AUTO.RIA теж,
сесія — у підписаній cookie. Єдине, що потребує уваги перед деплоєм, — **фото**.

## Що треба мати до початку

| Що | Навіщо | Скільки коштує |
|---|---|---|
| База PostgreSQL (Neon) | вона вже є — та сама, що локально | безкоштовний тариф |
| Обліковий запис Vercel | сам застосунок | Hobby вистачає |
| Бакет Cloudflare R2 | копії фото; **без нього їх не буде** | до 10 ГБ безкоштовно |
| Репозиторій на GitHub | деплой і розклад фонових задач | — |

### Чому R2 обовʼязковий

Локально копії фото лягають у теку `storage/` поруч із кодом. На Vercel файлова
система **тимчасова й лише для читання**: усе, що туди записалось, зникає з
наступним деплоєм, а перший же запис упав би з помилкою.

Тому без ключів R2 застосунок на Vercel свідомо перемикається в режим «сховища
немає»: копії фото не робляться, картки показують оригінальні адреси з
майданчика, у налаштуваннях у розділі «Дані» так і написано. Усе інше —
оголошення, ціни, події, Telegram — працює як завжди. Але «архів назавжди» зі
SPEC у такому режимі не виконується: зникне оголошення — зникнуть і фото.

## 1 · Бакет R2

1. Cloudflare → R2 → **Create bucket**, назва `car-hunt`;
2. **Manage R2 API Tokens** → Create API token → права **Object Read & Write**,
   тільки на цей бакет;
3. записати `Account ID`, `Access Key ID`, `Secret Access Key`.

Публічний домен бакета вмикати **не треба**: файли роздає наш роут
`/api/files/[...key]` під автентифікацією. Якщо колись увімкнеш — постав
`R2_PUBLIC_URL`, і роут перестане бути посередником.

## 2 · Проєкт у Vercel

**Add New → Project → Import** репозиторій. Налаштування збирання Vercel
визначає сам (Next.js), міняти нічого не треба.

Змінні оточення (Settings → Environment Variables), усі — для **Production**:

| Змінна | Значення |
|---|---|
| `DATABASE_URL` | той самий рядок Neon, що локально |
| `APP_PASSWORD` | пароль на двох |
| `USER_ME_NAME`, `USER_DAD_NAME` | імена в підписах подій |
| `SESSION_SECRET` | `openssl rand -hex 32` — підписує і сесію, і посилання на фото |
| `APP_URL` | `https://<проєкт>.vercel.app` — **без слеша в кінці** |
| `TELEGRAM_BOT_TOKEN` | від @BotFather |
| `TELEGRAM_CHAT_ID_ME`, `TELEGRAM_CHAT_ID_DAD` | приватні чати з ботом |
| `TELEGRAM_WEBHOOK_SECRET` | `openssl rand -hex 32` |
| `CRON_SECRET` | `openssl rand -hex 32` |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | з кроку 1 |
| `PARSER_SOURCE` | `html` |
| `CONTACT_EMAIL` | опційно: пошта в User-Agent наших запитів |

Повний перелік із поясненнями — у `.env.example`; він синхронний із кодом
(перевірено скриптом порівняння).

`APP_URL` можна заповнити лише після першого деплою, коли адреса відома. Тоді ж
його треба поставити і **передеплоїти**: за ним збираються посилання на картки в
Telegram і підписи на фото.

## 3 · Міграції

Схема застосовується **руками**, з ноутбука, у ту саму базу Neon:

```bash
npm run db:migrate
```

У збірку це не входить навмисно: міграції не мають виконуватись на кожному
холодному старті serverless-функції.

## 4 · Вебхук Telegram

Після першого вдалого деплою і виставленого `APP_URL`:

```bash
npm run tg:webhook -- --set --url https://<проєкт>.vercel.app
npm run tg:webhook            # перевірити, що адреса стала і помилок немає
```

Скрипт бере `TELEGRAM_WEBHOOK_SECRET` із `.env.local` — значення має **збігатись**
із тим, що у змінних Vercel, інакше роут відповідатиме 401 на все.

## 5 · Фонові задачі

Розклад живе в GitHub Actions (`.github/workflows/cron.yml`), бо Vercel Cron на
безкоштовному тарифі ходить лише раз на добу. У `vercel.json` лишається добовий
прогін як страховка.

У репозиторії (Settings → Secrets and variables → Actions) додати:

| Секрет | Значення |
|---|---|
| `APP_URL` | `https://<проєкт>.vercel.app` |
| `CRON_SECRET` | те саме, що у Vercel |

Перевірити руками:

```bash
curl -X POST "$APP_URL/api/cron/refresh" -H "Authorization: Bearer $CRON_SECRET"
curl -X POST "$APP_URL/api/cron/daily?force=1" -H "Authorization: Bearer $CRON_SECRET"
```

## 6 · Перевірка після деплою

| Крок | Очікуване |
|---|---|
| відкрити `APP_URL` | редирект на `/login`, сторінка входу |
| увійти паролем | черга авто |
| кинути посилання на auto.ria у поле вставки | картка зʼявилась, фото видно |
| `/settings` → «Дані» | «Фото у сховищі: N файлів» — якщо написано «сховище не налаштоване», перевір ключі R2 |
| написати боту `/start` | довідка у відповідь |
| переслати боту пост із групи | картка з телефоном і ціною з поста |
| `curl` крону з таблиці вище | `{"parsed":…}` замість 401 |

## Що перевірено перед деплоєм

- **збірка** чиста, `npm run lint` і `npm test` теж;
- **секрети не течуть у браузер**: у зібраних клієнтських файлах немає жодного
  значення з `.env.local` і жодного серверного модуля (drizzle, клієнт Bot API,
  підпис R2, парсер). Перевіряється пошуком по `.next/static`;
- **немає стану між запитами**: усе, що є на рівні модуля, — незмінні константи
  й кеші, які на холодному інстансі просто рахуються заново (ключ підпису сесії,
  `@username → chat_id`, обраний драйвер сховища). Черга альбомів, лічильник
  квоти AUTO.RIA і журнал спроб входу живуть у базі;
- **бюджет часу**: роути, які ходять у мережу (`/api/ingest`,
  `/api/telegram/webhook`, обидва крони), мають `maxDuration = 60`, а прогін
  крону сам зупиняється на 50-й секунді й дає наступному продовжити з того ж
  місця;
- **fallback без R2** описаний вище: застосунок працює, фото не зберігаються, і
  це видно в налаштуваннях.

## Відомі межі

- **пауза 2 с між запитами до майданчика** тримається в межах одного інстанса.
  На serverless паралельні інстанси можуть слати частіше; жорсткий ліміт
  (30/год, 1000/міс для API AUTO.RIA) рахується в базі й лишається чинним;
- **реалізація R2 не перевірена на живому бакеті** — вона написана вручну,
  без AWS SDK. Перший деплой варто закінчити перевіркою з таблиці вище: якщо в
  «Даних» фото не рахуються, дивись логи функції `/api/ingest`;
- **Hobby-тариф Vercel** дає максимум 60 с на функцію — цього вистачає, але
  оголошення з сорока фото архівуватиметься за кілька прогонів крону.
