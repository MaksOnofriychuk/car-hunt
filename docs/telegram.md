# Telegram-бот: вихідні повідомлення

Бот — це чат, у який застосунок сам пише нам двом. Нічого натискати в ньому поки
не треба: вхідні повідомлення (переслані пости, `/today`, відповіді реплаєм) —
окремий крок, тут тільки вихідні.

## Що і кому приходить

| Подія | Кому | Перемикач у налаштуваннях |
|---|---|---|
| Додали авто — посиланням або руками | **іншому**, не тому, хто додав | «Нове авто» |
| Записали дзвінок | іншому | «Коментарі і дзвінки» |
| Записали коментар | іншому | «Коментарі і дзвінки» |
| Змінили етап | іншому | «Зміни етапу» |
| Ціна в оголошенні змінилась | **обом** | «Зміни ціни» |

Правило «пишемо іншому, не автору дії» зі SPEC означає рівно те, що написано:
свої ж дії назад не прилітають. Виняток один — зміна ціни: її зробив продавець,
а не хтось із нас, тож «автора дії», якого треба обійти, немає.

Перемикачі й валюта беруться з налаштувань **отримувача**: якщо в батька стоїть
гривня, він побачить гривню, навіть коли ціну міняв я.

**Тихі години** (типово 22:00–08:00 за Києвом) не глушать повідомлення, а
знімають з нього звук. Загубити запис про дзвінок гірше, ніж тихо його
доставити.

Сповіщення ніколи не ламає саму дію: немає токена, Telegram не відповів, чат не
заданий — подія все одно записана, а в лог іде попередження `[telegram] …`.

## Налаштування

Змінні в `.env.local` (перелік — у `.env.example`):

```
TELEGRAM_BOT_TOKEN=""      # від @BotFather
TELEGRAM_CHAT_ID_ME=""     # мій chat_id
TELEGRAM_CHAT_ID_DAD=""    # батьків chat_id
APP_URL="https://…"        # публічна адреса застосунку
SESSION_SECRET=""          # ним же підписуються посилання на фото
```

`chat_id` — це не username. Найпростіше: кожен пише боту будь-що в приватний
чат, після чого

```bash
curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | grep -o '"chat":{"id":[0-9-]*'
```

покаже id того, хто щойно написав. **Поки людина не написала боту першою, бот їй
писати не може** — це правило Telegram, а не наше обмеження.

## Фото в повідомленнях

`/api/files/*` лежить під тією ж автентифікацією, що й увесь застосунок, а
Telegram ходить за картинкою своїм сервером, без наших cookie. Тому теку **не
відкрито**: замість цього кожне посилання підписується окремо
(`?exp=…&sig=…`, HMAC на `SESSION_SECRET`) і живе **одну годину**. Воно веде на
один конкретний файл — і тільки на нього.

- підпис перевіряє сам роут `/api/files/[...key]`;
- middleware лише пропускає запит із параметром `sig` далі, щоб не робити ту
  саму криптографію двічі; без валідного підпису роут віддає 401;
- якщо своєї копії фото ще немає, беремо адресу з майданчика;
- якщо Telegram не зміг забрати картинку, повідомлення йде **текстом** — картинка
  ніколи не з'їдає сам запис.

**На localhost фото не буде.** `APP_URL=http://localhost:3000` для серверів
Telegram — не адреса: `sendPhoto` віддасть `Bad Request: wrong HTTP URL
specified`, і з тієї ж причини слово «картка» не стане посиланням. Це очікувано.
Щоб побачити фото до деплою, підніми тунель (`cloudflared tunnel --url
http://localhost:3000` або `ngrok http 3000`) і встав його адресу в `APP_URL`.

## Як перевірити, що працює

### 1. Швидка перевірка, нічого не надсилаючи

```bash
npm run tg:check
```

Покаже: чи заданий токен, чи відповідає Bot API і під яким іменем, чи є `chat_id`
в обох, які в кожного перемикачі, котра зараз година в Києві й чи потрапляє вона
в тихі години, і яке фото піде в тесті.

### 2. Тестове повідомлення

```bash
npm run tg:check -- --send --to me   # тільки собі
npm run tg:check -- --send           # обом
```

Візьме **останнє реальне авто з бази** і надішле його як «нове авто» — так видно
справжній вигляд картки в месенджері. Якщо фото не пройде, скрипт скаже про це
окремим рядком і надішле текст: значить, недоступне саме фото, а не бот.

### 3. Наскрізна перевірка, як у житті

Заходити треба **різними людьми** — повідомлення йде іншому, тому самому собі ти
нічого не надішлеш.

| Що зробити | Що має прийти другому |
|---|---|
| Вставити посилання на auto.ria / OLX у поле на головній | «🚗 назва, рік · пробіг · місто, ціна · джерело, Додав …» з фото |
| «Додати вручну» і зберегти | те саме, без фото (якщо не додав) |
| На картці авто натиснути «Дзвінок» і записати результат | «📞 назва, хто дзвонив: результат · віддає $…, цитата» |
| Записати коментар | «💬 назва, хто записав, цитата» |
| «···» → змінити етап | «📌 назва, хто: етап «…»» |
| Вимкнути перемикач у **своїх** налаштуваннях і попросити другого зробити дію | **нічого** — перемикач читається в отримувача |
| Виставити тихі години на поточну годину | повідомлення приходить **без звуку** |

Зміну ціни руками не влаштуєш — вона приходить із майданчика. Щоб не чекати,
поки продавець її змінить: заниж ціну в базі й прожени парсер тим самим шляхом,
яким ходить cron.

```bash
psql "$DATABASE_URL" -c "update listings set price_usd = price_usd - 300 where source_id = '40252938'"
npm run parse -- 40252938
```

Парсер сходить на майданчик, побачить іншу ціну, запише подію `price_change` —
і обом прилетить «💸 назва — подорожчало, $X → $Y».

`npm run reparse` для цього **не годиться**: він перерозбирає збережений HTML і
подій ціни не пише.

## Що робити, якщо не працює

| Симптом | Причина |
|---|---|
| `TELEGRAM_BOT_TOKEN порожній` | немає змінної в `.env.local` |
| `Forbidden: bot was blocked by the user` | людина заблокувала бота — хай напише йому знову |
| `Bad Request: chat not found` | не той `chat_id`, або людина ще не писала боту |
| `Bad Request: wrong HTTP URL specified` | `APP_URL` не публічний — див. «Фото в повідомленнях» |
| Повідомлень немає, помилок теж | вимкнений перемикач в отримувача, або дію зробив він сам |
| У лозі `[telegram] …` | сповіщення не пройшло; сама подія записана й у стрічці є |

## Де що лежить

```
src/lib/telegram/api.ts        # клієнт Bot API: sendMessage, sendPhoto, getChat
src/lib/telegram/messages.ts   # тексти повідомлень, без мережі й бази
src/lib/telegram/notify.ts     # кому слати, чи слати взагалі, тихі години
src/lib/storage/signed.ts      # підписані посилання на фото
scripts/telegram-check.ts      # npm run tg:check
scripts/parse-one.ts           # npm run parse — прогнати парсер по одному авто
```

Точки, з яких воно викликається: `src/app/api/ingest/route.ts` (нове авто після
парсингу), `src/app/(app)/listing/actions.ts` (дзвінок, коментар, етап, ручне
додавання) і `src/lib/ingest.ts` (зміна ціни). Усюди через `after()` — відповідь
користувачу не чекає на Telegram.
