# Telegram-бот

Бот — це чат, у який застосунок сам пише нам двом, і водночас найкоротший шлях
щось йому сказати: кинути посилання, переслати пост із групи, відповісти
реплаєм замість того, щоб відкривати застосунок.

Нижче спершу вихідні (що бот пише сам), потім вхідні (що він розуміє від нас).

## Що і кому приходить

| Подія | Кому | Перемикач у налаштуваннях |
|---|---|---|
| Додали авто — посиланням або руками | **іншому**, не тому, хто додав | «Нове авто» |
| Записали дзвінок | іншому | «Коментарі і дзвінки» |
| Записали коментар | іншому | «Коментарі і дзвінки» |
| Змінили етап | іншому | «Зміни етапу» |
| Ціна в оголошенні змінилась | **обом** | «Зміни ціни» |

Правило «пишемо іншому, не автору дії» зі SPEC означає рівно те, що написано:
свої ж дії назад не прилітають. Виняток один — зміна ціни: її зробив продавець,
а не хтось із нас, тож «автора дії», якого треба обійти, немає.

Перемикачі й валюта беруться з налаштувань **отримувача**: якщо в батька стоїть
гривня, він побачить гривню, навіть коли ціну міняв я.

**Тихі години** (типово 22:00–08:00 за Києвом) не глушать повідомлення, а
знімають з нього звук. Загубити запис про дзвінок гірше, ніж тихо його
доставити.

Сповіщення ніколи не ламає саму дію: немає токена, Telegram не відповів, чат не
заданий — подія все одно записана, а в лог іде попередження `[telegram] …`.

## Налаштування

Змінні в `.env.local` (перелік — у `.env.example`):

```
TELEGRAM_BOT_TOKEN=""      # від @BotFather
TELEGRAM_CHAT_ID_ME=""     # мій chat_id
TELEGRAM_CHAT_ID_DAD=""    # батьків chat_id
APP_URL="https://…"        # публічна адреса застосунку
SESSION_SECRET=""          # ним же підписуються посилання на фото
```

`chat_id` — це не username. Найпростіше: кожен пише боту будь-що в приватний
чат, після чого

```bash
curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | grep -o '"chat":{"id":[0-9-]*'
```

покаже id того, хто щойно написав. **Поки людина не написала боту першою, бот їй
писати не може** — це правило Telegram, а не наше обмеження.

## Фото в повідомленнях

`/api/files/*` лежить під тією ж автентифікацією, що й увесь застосунок, а
Telegram ходить за картинкою своїм сервером, без наших cookie. Тому теку **не
відкрито**: замість цього кожне посилання підписується окремо
(`?exp=…&sig=…`, HMAC на `SESSION_SECRET`) і живе **одну годину**. Воно веде на
один конкретний файл — і тільки на нього.

- підпис перевіряє сам роут `/api/files/[...key]`;
- middleware лише пропускає запит із параметром `sig` далі, щоб не робити ту
  саму криптографію двічі; без валідного підпису роут віддає 401;
- якщо своєї копії фото ще немає, беремо адресу з майданчика;
- якщо Telegram не зміг забрати картинку, повідомлення йде **текстом** — картинка
  ніколи не з'їдає сам запис.

**На localhost фото не буде.** `APP_URL=http://localhost:3000` для серверів
Telegram — не адреса: `sendPhoto` віддасть `Bad Request: wrong HTTP URL
specified`, і з тієї ж причини слово «картка» не стане посиланням. Це очікувано.
Щоб побачити фото до деплою, підніми тунель (`cloudflared tunnel --url
http://localhost:3000` або `ngrok http 3000`) і встав його адресу в `APP_URL`.

## Як перевірити, що працює

### 1. Швидка перевірка, нічого не надсилаючи

```bash
npm run tg:check
```

Покаже: чи заданий токен, чи відповідає Bot API і під яким іменем, чи є `chat_id`
в обох, які в кожного перемикачі, котра зараз година в Києві й чи потрапляє вона
в тихі години, і яке фото піде в тесті.

### 2. Тестове повідомлення

```bash
npm run tg:check -- --send --to me   # тільки собі
npm run tg:check -- --send           # обом
```

Візьме **останнє реальне авто з бази** і надішле його як «нове авто» — так видно
справжній вигляд картки в месенджері. Якщо фото не пройде, скрипт скаже про це
окремим рядком і надішле текст: значить, недоступне саме фото, а не бот.

### 3. Наскрізна перевірка, як у житті

Заходити треба **різними людьми** — повідомлення йде іншому, тому самому собі ти
нічого не надішлеш.

| Що зробити | Що має прийти другому |
|---|---|
| Вставити посилання на auto.ria / OLX у поле на головній | «🚗 назва, рік · пробіг · місто, ціна · джерело, Додав …» з фото |
| «Додати вручну» і зберегти | те саме, без фото (якщо не додав) |
| На картці авто натиснути «Дзвінок» і записати результат | «📞 назва, хто дзвонив: результат · віддає $…, цитата» |
| Записати коментар | «💬 назва, хто записав, цитата» |
| «···» → змінити етап | «📌 назва, хто: етап «…»» |
| Вимкнути перемикач у **своїх** налаштуваннях і попросити другого зробити дію | **нічого** — перемикач читається в отримувача |
| Виставити тихі години на поточну годину | повідомлення приходить **без звуку** |

Зміну ціни руками не влаштуєш — вона приходить із майданчика. Щоб не чекати,
поки продавець її змінить: заниж ціну в базі й прожени парсер тим самим шляхом,
яким ходить cron.

```bash
psql "$DATABASE_URL" -c "update listings set price_usd = price_usd - 300 where source_id = '40252938'"
npm run parse -- 40252938
```

Парсер сходить на майданчик, побачить іншу ціну, запише подію `price_change` —
і обом прилетить «💸 назва — подорожчало, $X → $Y».

`npm run reparse` для цього **не годиться**: він перерозбирає збережений HTML і
подій ціни не пише.

## Що робити, якщо не працює

| Симптом | Причина |
|---|---|
| `TELEGRAM_BOT_TOKEN порожній` | немає змінної в `.env.local` |
| `Forbidden: bot was blocked by the user` | людина заблокувала бота — хай напише йому знову |
| `Bad Request: chat not found` | не той `chat_id`, або людина ще не писала боту |
| `Bad Request: wrong HTTP URL specified` | `APP_URL` не публічний — див. «Фото в повідомленнях» |
| Повідомлень немає, помилок теж | вимкнений перемикач в отримувача, або дію зробив він сам |
| У лозі `[telegram] …` | сповіщення не пройшло; сама подія записана й у стрічці є |

користувачу не чекає на Telegram.

# Вхідні

`POST /api/telegram/webhook`. Роут тонкий: перевіряє секретний заголовок, кладе
апдейт у чергу і **одразу відповідає 200** — інакше Telegram вважає доставку
невдалою і шле той самий апдейт ще раз.

## Що бот розуміє

| Що надіслати | Що станеться |
|---|---|
| посилання на AUTO.RIA / OLX | картка створюється, у відповідь «Додав: назва — ціна» з кнопкою |
| те саме посилання вдруге | «Це авто вже є», другої картки немає |
| **переслати пост** із групи | злиття з карткою за посиланням із поста, а якщо посилання немає — картка з самого поста |
| альбом фото | один пост, усі фото, жодного дубля |
| реплай на будь-яке повідомлення бота про авто | коментар у стрічці того авто |
| `/today` | кому дзвонити сьогодні, прострочене вгорі |
| `/start`, `/help` | коротка довідка і твій `chat id` |

Усе, що прийшло не від нас двох, отримує тиху 200 і не обробляється.

## Пости: злиття, а не дубль

Головне правило: **є в пості посилання на оголошення — картка створюється за
ним**, звичайним інгестом і звичайним парсером. Дані поста лягають зверху
доповненням і **тільки в порожні колонки**. Двох карток про одне авто не буває.

Що дає пост, чого немає в оголошенні:

- **повний телефон** — на сторінці RIA його не побачити взагалі;
- **реальну ціну** («9500$ (ріа 9799$)»): перше число йде в `price_from_post` і
  показується на картці поруч із ціною оголошення, друге лишається довідкою;
- VIN, контакт продавця (`@nickname`), дату й текст поста.

Пост ніколи не затирає непорожнє поле парсера. Виняток один — VIN: AUTO.RIA
кладе в ту саму колонку **маску** (`1HGCR2650EA7XXXXX`), тому повний VIN із
поста перемагає її.

Ціни з постів **не потрапляють** в історію цін оголошення: подія «ціна впала»
від постів пишеться лише тоді, коли ціна змінилась **між двома постами** в тій
самій валюті. 9500 у пості проти 9799 в оголошенні — це знижка, а не падіння, і
черга показала б фальшиве «↓».

Телефон іде тим самим шляхом, що й уведений руками: продавці **не зливаються
автоматично**. Номер уже є в когось — на картці зʼявиться звичне попередження
«цей номер уже записаний у…».

## Альбоми

Telegram шле альбом кількома апдейтами з одним `media_group_id`, а підпис кладе,
як правило, у перше повідомлення. Тому кожен апдейт спершу лягає в
`telegram_inbox`, і лише через паузу (`TELEGRAM_ALBUM_DELAY_MS`, типово 3000 мс)
обробляється **вся група разом**. Обробник рівно один — його визначає атомарний
`claim` у базі.

Якщо інстанс помер посеред обробки, група лишається необробленою: її добирає
`sweepStaleInbox` — і з крону, і на наступному вхідному апдейті.

## Як поставити вебхук

Telegram вимагає **публічну https-адресу**. З localhost вебхук не працює взагалі.

```bash
# 1. секрет, яким Telegram підписує кожен запит
openssl rand -hex 32          # → TELEGRAM_WEBHOOK_SECRET у .env.local

# 2. тунель на час локальної перевірки
cloudflared tunnel --url http://localhost:3000

# 3. реєстрація (адреса — з тунелю або APP_URL)
npm run tg:webhook -- --set --url https://xxx.trycloudflare.com

# стан, остання помилка доставки, розмір черги
npm run tg:webhook

# зняти
npm run tg:webhook -- --delete
```

`npm run tg:webhook` без прапорців нічого не міняє — лише показує, куди зараз
налаштований бот і що Telegram відповів останнього разу.

## Наскрізна перевірка

Після `--set` надішли боту по черзі:

1. `/start` — має відповісти довідкою і показати твій `chat id`;
2. посилання на auto.ria — «Додав: …» і картка в черзі;
3. те саме посилання ще раз — «Це авто вже є»;
4. переслати пост із групи, де є фото, телефон і посилання на RIA — **одна**
   картка з даними RIA, телефон у продавця, ціна з поста і блок «З Telegram»;
5. переслати той самий пост удруге — «Цей пост уже є»;
6. переслати альбом на кілька фото — один пост і всі фото;
7. переслати пост **без** посилання — картка з самого поста: те, що впізналось,
   у колонках, решта — текстом;
8. відповісти реплаєм на будь-яке повідомлення бота про авто — коментар у стрічці;
9. `/today` — список на сьогодні.

Якщо щось не дійшло, перший діагноз — `npm run tg:webhook`: там видно
`last_error_message` від самого Telegram.

## Що робити, якщо не працює

| Симптом | Причина |
|---|---|
| у `getWebhookInfo` порожня адреса | вебхук не поставлений: `npm run tg:webhook -- --set` |
| `Wrong response from the webhook: 401` | не збігається `TELEGRAM_WEBHOOK_SECRET` між `.env` і тим, що зареєстровано |
| бот мовчить на все | адреса тунелю змінилась — постав вебхук заново |
| пост завів другу картку замість злиття | у пості немає посилання на оголошення, або воно в рядку про кредит — такі посилання ігноруються навмисно |
| фото поста немає | не вистачило часу на завантаження; добере `POST /api/cron/refresh` |
| «Не знаю, до якого авто це» | реплай не на повідомлення бота про конкретну картку |
