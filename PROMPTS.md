# Промти для Claude Code — проєкт Car Hunt

Вставляй по черзі. Кожен наступний — тільки після того, як перевірив результат попереднього.

---

## Крок 0. Підготовка (у терміналі Mac)

```bash
curl -fsSL https://claude.ai/install.sh | bash
mkdir -p ~/projects/car-hunt && cd ~/projects/car-hunt
```

Поклади `SPEC.md` у цю папку. Далі:

```bash
claude
```

При першому запуску залогінишся через браузер. Потрібен платний план (Pro / Max / Team / Enterprise або Console) — на безкоштовному Claude Code не працює.

Далі всі промти вставляєш всередині сесії `claude`.

## Промт 2 — база даних

```
Тепер налаштуй Drizzle ORM + PostgreSQL згідно з розділом «Модель даних» у SPEC.md.

Зроби:
- схему в src/db/schema.ts з усіма чотирма таблицями
- drizzle.config.ts, скрипти db:generate / db:migrate / db:studio у package.json
- src/db/index.ts з клієнтом
- .env.example з усіма змінними, які знадобляться далі
- сідер scripts/seed.ts, який додає 3 тестові авто з фейковими даними, щоб можна було дивитись інтерфейс без парсера

Поточний етап авто НЕ зберігай полем — обчислюй з останньої події stage_change. Зроби для цього хелпер.

Не запускай міграції — я спершу вставлю DATABASE_URL.
```

Після цього: заведи безкоштовну базу на Neon або Supabase, встав `DATABASE_URL` у `.env.local`, потім скажи Claude Code `запусти міграції і сідер`.

## Промт 4 — інгест і парсер

```
Реалізуй інгест посилань згідно з розділами «Інгест посилання» і «Парсер» у SPEC.md.

Почни з src/lib/autoria/url.ts — функція extractAutoRiaId. Напиши на неї юніт-тести (vitest) з усіма форматами посилань зі SPEC, включно з пересланим текстом і UTM-хвостами. Спершу тести, потім реалізація, і покажи що вони проходять.

Далі — POST /api/ingest з негайною відповіддю і фоновим парсингом, обидві реалізації ListingSource (api і html), лічильник ліміту 30 запитів/годину.

У .env постав PARSER_SOURCE=html за замовчуванням — API-ключа в мене поки нема.
```

⚠️ Реальний формат сторінки AUTO.RIA він точно не вгадає з першого разу. Тому наступний крок:

```
Ось справжнє посилання на оголошення: <ВСТАВ СВОЄ ПОСИЛАННЯ>

Завантаж цю сторінку, подивись, що там реально в ld+json і у вбудованому JSON, і допили парсер під фактичну структуру. Покажи мені, які поля вдалося витягти.
```

## Корисне під час роботи

| Що | Команда |
|---|---|
| Почати нову сесію з чистим контекстом | `/clear` |
| Оновити CLAUDE.md після великих змін | `/init` |
| Діагностика встановлення | `claude doctor` |
| Відкотити невдалу правку | `git checkout .` (тому коміть часто) |

Три звички, які найбільше економлять час:

1. **Коміть після кожного промту**, який дав робочий результат. Скажи Claude Code «зроби коміт» — він напише повідомлення сам.
2. **Не приймай код, який не запускав.** Після кожного кроку — `npm run dev` і подивись очима.
3. **Коли щось не працює — не описуй симптом, дай помилку.** Встав повний текст помилки з терміналу або консолі браузера.

І окремо: якщо правка стосується конкретного файлу — називай файл. «Поправ картку авто» дає гірший результат, ніж «у src/components/ListingCard.tsx зроби ціну більшою за назву».
